# ChatWave backend (Phase 1)

Node.js + TypeScript + Express + Socket.IO + PostgreSQL. Companion repo: `chatwave-android`.

**Security note:** v1 uses TLS in transit and server-readable message storage. It is **not** end-to-end encrypted.

## Local development
1. `cp .env.example .env` and set `DATABASE_URL`, `JWT_ACCESS_SECRET` (>= 32 chars).
2. Create a Postgres DB (e.g. `createdb chatwave`; a second one `chatwave_test` for tests).
3. `npm install && npm run dev` — migrations run automatically on startup (`npm run migrate` runs them alone).
4. Tests: `TEST_DATABASE_URL=postgres://.../chatwave_test npm test`.

## REST (`/api/v1`)
| Method | Path | Auth | Notes |
|---|---|---|---|
| POST | /auth/register | no | `{username, password, displayName}` -> 201 `{user, accessToken, refreshToken, expiresIn}`; 409 duplicate |
| POST | /auth/login | no | generic 401 on failure |
| POST | /auth/refresh | no | rotates refresh token; reuse revokes the family |
| POST | /auth/logout | no | `{refreshToken}` -> 204, revokes the session family |
| GET | /users/me, /users/search?q=, /users/:id | yes | search needs q >= 2 chars |
| GET | /chats | yes | conversations with last message + unread count |
| POST | /chats/direct | yes | `{userId}` -> existing or new direct conversation |
| GET | /chats/:id/messages?before=&limit= | yes | cursor = `seq`; response `{items, nextBefore}`; 403 for non-members |

Errors: `{ "error": { "code", "message", "details?" } }`. Health: `GET /health`, `GET /ready`.

## Socket.IO
Connect with `auth: { token: <accessToken> }`. Client -> server (all take an ack callback):
`message:send {conversationId, clientMessageId(uuid), body}` -> ack `{ok, message, duplicate}` (sent only after DB commit),
`message:delivered {messageIds[]}`, `message:read {conversationId, upToSeq}`, `typing:start|stop {conversationId}`.
Server -> client: `message:new`, `message:delivered`, `message:read`, `typing:start|stop`, `presence:update`.
Reconnect recovery: fetch `/chats` and `/chats/:id/messages` after reconnecting; resend unacked messages with the same `clientMessageId`.

## Deploy (Render)
The root `render.yaml` is a Blueprint that creates both the web service and a PostgreSQL database.

1. Push this project to a GitHub repository.
2. In Render, choose **New -> Blueprint**, select the repository, and apply `render.yaml`.
3. Wait for the database migration and web service deploy to complete.
4. Verify `https://<your-service>.onrender.com/health` returns `{"status":"ok"}`.
5. Use the resulting HTTPS service URL as the Android production URL.

`DATABASE_URL` is injected from the Render database and `JWT_ACCESS_SECRET` is generated by Render.
The free web service may sleep after inactivity, so the first request can take up to a minute.
Free database availability, storage, and retention depend on Render's current plan terms; do not use it for irreplaceable data without backups.
